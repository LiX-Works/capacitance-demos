# HTML / WebGL 实现与 QA

## 1. 技术实现方向
可以部分沿用之前 ProxiTouch 已经验证过的工程经验：
- 原生 WebGL2 或当前已有的轻量 3D 渲染框架；
- Scene / beat 驱动的知识单元；
- 一页一个主要认知任务；
- 支持自动播放与手动导航；
- 关键场景支持暂停在最终帧；
- 必要时保留 Explore 模式；
- 单文件离线 HTML 优先；
- 不依赖在线 CDN；
- 数值数据可以预计算后内嵌，避免课堂运行时求解过慢。

## 2. 统一参数源
这是本项目非常重要的实现原则：

**3D 模型、解析曲线、数值仿真、图表和文字标注必须共享同一套几何参数。**

不要出现：
- 3D 模型的 gap 是一套数值；
- 解析公式又使用另一套；
- 数值仿真再画一个差不多的几何。

建议建立统一参数对象/配置，例如包含：
L、b、D、δ、g、θ、介质位置、t、εr 等。

## 3. 数值数据实现
课堂 HTML 不一定要实时解 PDE。

更稳妥的方式通常是：
1. 离线高质量计算参数扫描；
2. 保存代表性场数据与 C(θ)；
3. HTML 中插值播放；
4. Explore 模式根据 θ 连续插值；
5. 对关键角度展示真实计算数据，而不是纯视觉插值冒充求解结果。

如果你认为浏览器实时求解足够稳定，也可以实现，但要优先保证课堂运行可靠。

## 4. 视觉 QA
检查：
- 转轴是否真的固定；
- 上板是否只有旋转而没有隐藏平移；
- 180° 后两板是否真正共面；
- gap 是否和 δ 的几何关系一致；
- 角度标注与实际模型一致；
- 电极没有穿插；
- 介质没有漂浮或穿模；
- 场线与导体表面关系合理；
- 最终帧即使不播放动画也能看懂。

## 5. 物理 QA
至少检查：
- 解析式的几何前提是否与页面模型一致；
- 数值边界条件是否清楚；
- 绝对电容单位是否正确；
- 2D 到真实宽度的换算是否正确；
- 归一化曲线与绝对值曲线是否来自同一数据；
- 介质模型是否使用真实空间 ε(x,y)；
- 不把“示意场线”写成“严格仿真结果”；
- 不把理想扇区模型写成真实有限极板的精确解；
- 如果使用近似模型，页面上应说明它的假设与用途。

## 6. 文案 QA
- 删除“神奇”“偷懒”“小技巧”等刻意语言；
- 删除论文套话；
- 每页标题应能直接回答“这一页在干什么”；
- 字号不能为了塞内容而变小；
- 一般不使用小号副标题；
- 公式旁边必须有一句正常语言解释其物理意义；
- 重要结论应清楚可读，不要藏在脚注里。

## 7. 最终交付 QA
完成后请实际：
- 离线打开 HTML；
- 检查 WebGL2 是否正常；
- 从头到尾完整播放；
- 检查导航、回退、重播；
- 检查 Explore（若有）；
- 检查所有图表、单位、公式和最终帧；
- 在常见 16:9 桌面分辨率下检查排版；
- 记录关键模型参数和仿真来源，便于课堂问答。
